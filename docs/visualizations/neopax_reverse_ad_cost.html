Why reverse AD costs roughly three forward solves

Compute the trajectory once. Reconstruct each segment from a checkpoint, then differentiate it backward. Only the current segment needs its detailed Radau records in memory.

1. Adaptive forward solve

Advance the physical solution to the final time. Record the accepted timesteps and sparse checkpoint carries. Rejected trials are discarded from the accepted trajectory.

2. Forward reconstruction

Restore a checkpoint and replay its accepted steps in the forward direction. Rebuild the internal stages and records needed by the local derivative. Do this for one segment at a time.

3. Backward adjoint sweep

Move the objective sensitivity backward through the reconstructed steps and accumulate parameter sensitivities. Release the segment's temporary records, then repeat for the previous segment.

Approximately 3× is a work estimate, not a measured runtime guarantee. The meter assigns equal cost to a full forward trajectory, a full replay and a full adjoint sweep. Real costs differ; compilation, VMEC/NTX, objective batching, support pullbacks and checkpoint setup can add work. The two lower lanes run alternately, segment by segment.

What is actually saved, and how this maps to the current source

The circles represent the evolving profiles, not a complete solver carry. A checkpoint also contains the numerical and transport state required for faithful replay. The stored schedule is lightweight metadata with O(N) entries; it is not a tape of every heavy carry or every Radau stage.

This animation shows the path that receives checkpoint carries from the adaptive run. In NEOPAX/_transport_solvers.py, _radau_adaptive_final_y_realized_schedule_vjp_fwd_from_schedule_artifact reuses segment_start_carries_artifact when available. Other paths can perform an additional accepted-schedule pass to build those checkpoints. Reusing a schedule alone does not prove that all such work was eliminated.

In NEOPAX/_reverse_ad_transport.py, the support reverse sweep restores each segment, obtains step_start_carries and step_primal_records, and runs accepted-step pullbacks in reverse order. In the recorded-forward reuse path, accepted-step Newton reuse decisions are retained without differentiating rejected attempts. The physical solution is not integrated backward in time, and the timestep controller is not differentiated in this accepted-schedule contract.

The schematic's three blocks do not claim that all reverse configurations have identical computation or memory. Checkpoint carries, stage records, shared database/support arrays and batched cotangents have different sizes. The buffer drawing counts records, not bytes. Increasing the segment size uses more temporary records and fewer checkpoint boundaries.

The final parameter pullback also includes initial profiles, the selected initial electric-field root, and geometry/database dependencies as applicable. Their cost is outside the equal-cost timeline. This page is an offline explanatory animation; it runs no transport, VMEC or NTX calculations.
